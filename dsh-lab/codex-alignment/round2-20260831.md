# Round-two behavioral validation

Official immutable DSH reference: `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`.
Host under test: official DSH `0.1.0-rc.8`; native executable:
`0.151.0-alpha.7.2`. Private transcripts and test artifacts remain outside Git.

## Cancellation finding

An instrumented real-model run observed this ordering:

1. The fixture child process had already started.
2. The native background-terminal list was empty.
3. `turn/interrupt` returned and `turn/completed` reported `interrupted`.
4. About 49 ms later, `item/started` announced the command and its process ID.

Repeated before/after interruption inventory queries were insufficient. The
runtime now records interrupted turn IDs and terminates command processes that
arrive late for those exact turns through the native termination RPC. It does
not discover or kill arbitrary operating-system processes. Duplicate events
are deduplicated by item/process identity; a new turn's commands are unaffected.
Late items, plans, diffs and output deltas no longer reopen terminal turns. Failed late cleanup
produces a diagnostic and an error activity instead of being silently swallowed.

`cancel-trace.mjs` records event timestamps, background inventories, RPC results,
and the fixture's independently observed PID state. The old implementation
failed 2/6 runs; the fix passed 20/20 with cancellation immediately after child
startup, after 100 ms and after 1 second. Seven runs contained a command-start
notification after the interrupted-turn completion. The maximum observed child
stop time after requesting cancellation was 69 ms. These are sample results,
not a universal timing guarantee. Only the trace driver's cleanup may signal its
own fixture PID after a failed test; that is not part of plugin implementation.

A follow-up regression test also delivered late command output after an
interrupted turn and a new turn's start. It reproduced a separate status reset
in `applyDelta`; the same preserve-terminal-status rule is now used there.
The pre-fix failing test and subsequent full verification are retained. This
small final guard is distinguished from the earlier benchmark package by hash.

## Additional acceptance

The suite adds controlled loopback HTTP failure cases: definitive 404, one 503
followed by success, and a response slower than the request deadline. The model
must classify results, limit retries and preserve failures. The service controls
responses; model choices and tool execution are real, not replayed.

Long-context acceptance changes requirements across ten input turns, restarts the
DSH host, explicitly compacts the native thread and asks for the current final
requirements without filesystem lookup. The same thread ID and native
`contextCompaction` item are required evidence. Manual compaction is performed
after stopping DSH and releasing its native writer, then DSH is resumed; this
does not claim that a DSH UI compaction button exists.

The first enhanced-mode run failed a literal-string oracle because its forbidden
actions included the equivalent prefix “禁止”. The original failure is retained;
a separate semantic verification accepts the correct meaning, and the subsequent
oracle normalizes only explicit prohibition prefixes and array order. It still
checks all current values, no shell calls, and thread continuity.

## True Desktop comparisons

`paired-fixtures.mjs` builds separate but equivalent App/DSH tasks for code repair,
CSV processing (including quoted fields, multiline cells and deduplication) and
release-status lookup against a controlled registry. Each task is repeated twice.
The user authorized independent test conversations. App cases are actual local
tasks created and run by Codex Desktop, not a direct App Server client labeled
as Desktop. DSH uses the same native binary, model, reasoning effort, access mode
and corresponding App working directory. Fixture paths and registry namespaces
differ to preserve independent outcomes and request logs.

Oracles independently run unchanged tests, compare exact data/status outputs,
and verify protected input hashes. Count model tool calls and underlying command
failures separately. A failed test before repair is an expected negative result;
a missing tool dependency or unnecessary retry is not. Retain all samples,
including slower ones. Two repetitions and three small task types cannot prove
general intelligence parity or cover all Desktop-only host capabilities.

The initial six pairs all passed independent output and protected-file checks.
Across these pairs App used 24 model tool calls and DSH used 24, with means of
26.199 and 31.328 seconds respectively. The code repair cases account for most
of the difference: DSH guessed `qty` on both attempts before correcting to
`quantity`; App also made unnecessary Git/path checks that failed. Expected
pre-repair failing tests are reported separately from those mistakes. All four
lookup tasks made exactly one request per package, including the missing one.

Because “do not read harness files” might be confused with a prohibition on
reading project tests, a separate sensitivity check explicitly permits reading
project tests without giving the missing field name. Keep those new cases
separate from the original measurements; do not erase the slow samples.

Both clarified pairs passed with one patch per task and four model tool calls
on both engines. App durations were 22.974/28.076 seconds; DSH durations were
24.114/31.057 seconds. The initial incorrect-field guess did not recur. This
supports sensitivity to task wording, not a claim that all remaining behavioral
differences are caused by wording. These two DSH tasks used the final package
with the additional late-output status guard; the earlier six used its predecessor.

Approval allow/deny passed through all three suite engines. An error-fidelity
case in DSH native mode exposed missing error text in the native command item,
although the model-visible result and final answer retained it. This is an
unresolved failed acceptance, documented in `native-empty-output.md`, not a
failure to ask for approval. A separate enhanced-mode run passed the same case.
