# 选题简报

- 主题：把 Codex 和 Claude Code 接入 DeepSeek Harness 后，为什么还要做 162 项迁移测试
- 主类型：实测复盘 / 观点分析
- 次类型：插件工具软推广、跨平台改写
- 目标读者：已经用 Codex 或 Claude Code 做真实项目，正在考虑统一项目入口、导入旧会话或尝试 DSH 插件的用户
- 读者问题：看到插件可以正常聊天后，怎样判断图片、长命令、中断、旧会话和敏感信息等真实工作能力是否也能可靠使用
- 文章承诺：用三个具体失败案例解释“能回复不等于迁移完成”，给出一套普通用户也能使用的迁移判断方法
- 核心观点：迁移不是把模型名字放进新界面，而是原来的任务、会话和安全边界能否继续成立
- 关键证据：2026 年 8 月 29 日完成 162 项原子能力验证，Codex 76 项、Claude 86 项，共保留 167 次运行；发现图片未进入 Codex、界面停止但子进程继续、敏感值进入持久记录等问题
- 时间边界：59/6/11 和 78/3/5 是 8 月 29 日发现问题时的快照，不是 8 月 30 日新版本的当前通过率
- 当前版本：Codex 插件 0.1.3；Claude 插件 0.1.4。两版已经针对图片输入、命令输出、中断、敏感值、旧会话导入等问题做了修复或补强，完整 162 项回归仍需重新完成后才能发布新矩阵
- 术语策略：首次出现时分别用一句白话解释 DSH、Codex、Claude Code 和插件；正文不展开 App Server、Agent SDK、Thread、Session Runtime 等实现名词
- 图片计划：1 张 DSH 中使用 Codex 的真实界面；1 张 162 项测试结果信息图；1 张“停止前/停止后”的真实测试截图组合
- 计划长度：2200-2800 字
- CTA：先按自己的高频任务列出迁移清单，再决定哪些任务可以试用插件、哪些暂时保留在原生工具中

## 标题方向

首选：

> 把 Codex 和 Claude Code 放进同一个工作台，原来的功能还能用吗？

备选：

1. 换个界面继续用 Codex 和 Claude Code，原来的功能会丢吗？
2. 图片看得见，AI 却没收到：两个 AI 编程插件的 162 项实测
3. 把 Codex 和 Claude Code 搬进新界面后，我们发现“能回复”远远不够

## 结构

1. 从一个反常场景开头：界面有图片，模型却没收到
2. 用白话说明 DSH 和两个插件在做什么
3. 解释为什么“一次成功对话”不能证明迁移完成
4. 给出 162 项测试快照，并明确时间边界
5. 展开三个最有用户感知的失败案例
6. 说明测试如何直接推动新版本修复
7. 给读者一张迁移判断清单
8. 公开当前边界和相关链接
